# Spike: Subtitle translation

Branch: `spike/subtitle-translation` (child of `spike/live-subtitles`)

## Status and how to resume

_Last updated 2026-10-19._

**Where things stand:** live translation is built and works in the running app (tried with English to German, which ran close to real time). Steps 1 (benchmark), 2 (native build check) and 3 (live translation in the app) are done, and the language pairs have been extended beyond German and French. Open items are under "Not done yet".

**What exists:**

- `src-tauri/vendor/ct2rs/`: patched `ct2rs` 0.10.1 wired in with `[patch.crates-io]` (12 MB; changes listed in `GLUCOSE_PATCHES.txt`). Features `ruy` and `sentencepiece`, no MKL. Decision (2026-10-11): keep it vendored in the repo; see "Step 2".
- `src-tauri/src/translate.rs`: a list of models, each with a source and a target language. `CueTranslator` loads one and translates a chunk's cues: it groups cues into sentences, translates them in one batch, spreads each translation over the source cues' time span in proportion to text length (keeping pauses between cues), then runs the result through `build_cues`, so the target language gets its own line breaks and reading-speed timing.
- Live worker (`live_subtitles.rs`): `start_live_subtitles` takes `translate_to` and fails early if no installed model translates into that language. For each chunk it picks the model from the speech language (the one set in Settings, or the one Whisper detects), loads it on first use and caches it for the session (released on unload). Speech already in the target language, or in a language no model covers, is shown unchanged, and a translation error falls back to the original text for that chunk.
- Live cache key includes `translate_to` (omitted when not translating, so existing caches still match).
- Settings, AI tab, Live Subtitles: "Translate live subtitles": Off, German, French, Spanish, Russian, Turkish, Italian, Dutch or English (`localStorage` key `glucose_live_translate`), applied the next time live subtitles start. The subtitle menu entry and the status text name the language ("Live subtitles · small-q5_1 · German", "Generating German subtitles...", "Loading German translation model...").
- **Language pairs:** from English into German, French, Spanish, Russian, Turkish, Italian and Dutch (compact `opus-mt_tiny_eng-*` models, about 20 MB each), and into English from the same seven languages (compact `opus-mt_tiny_*-eng`). All were converted, installed on the development machine and sanity-checked on a few sentences each; only German and French output has been reviewed for quality. No compact Finnish model exists, so Finnish is not offered.
- Models are looked up as `<model folder>/<model name>/` (CTranslate2 int8 conversion plus `source.spm` and `target.spm`), in the same folders as the Whisper models.
- **Downloading the models (`translation_models.rs`):** Settings, AI tab, "Translation models" lists the 14 pairs with Download, a progress bar and Remove. The converted models are release files of the public `rudi-q/glucose-translation-models` repository (release `v1`, files named `<model folder>__<file>`), since the published originals are PyTorch models the app cannot load and no converted copies of the compact models exist elsewhere. Every file's SHA-256 is pinned in the app and checked before installing; a download goes into a temporary folder that only replaces the model once complete, and an existing copy is kept until the new one is in place. Adding a model means converting it, uploading its five files to the release and adding its five checksums in `translation_models.rs`.
- Tests: unit tests cover sentence grouping and word placement; `translates_real_cues_with_installed_model` (ignored by default, run with `cargo test --lib -- --ignored`) translates real cues with the installed German model.

## Background

Relevant public work: the Bergamot project (browser.mt) produced compact MT models that run on CPU; Helsinki-NLP's OpusDistillery pipeline builds on it; Marian-NMT's guided alignment can train an attention head to follow word alignments; and OPUS-MT-app is an on-device desktop demo.

- Bergamot's own runtime (`bergamot` on PyPI) does not build on Windows, so Mozilla's Bergamot models were not tested directly.
- Helsinki-NLP publishes compact distilled models in the standard Hugging Face Marian format (`opus-mt_tiny_*`, Apache-2.0), which CTranslate2 can convert and run. These stand in for the Bergamot-style compact models.
- Tauri does not use Chrome's translation: it runs in WebView2 (Windows), WebKit (macOS) and WebKitGTK (Linux), so the app must ship its own MT engine.

## Step 1: benchmark (2026-10-06)

Input: the 123 cues from the live subtitle cache of a 7-minute English academic talk (0-415 s, Whisper `small-q5_1`, current cue formatter), joined and re-split into 73 sentences. Real Whisper output, including its errors (for example a misheard programme name).

Engine: CTranslate2 4.8.2, int8 weights (int8_float32 compute on this CPU), 4 threads, beam size 2. Each model ran in its own process. Machine: 20 logical cores.

| Model | Size int8 | Load | Memory | Per cue (mean / p95) | Words/s (batched sentences) | chrF vs big |
|---|---|---|---|---|---|---|
| opus-mt_tiny_eng-deu | 18 MB | 0.8 s | 45 MB | 18 / 30 ms | 1066 | - |
| opus-mt-en-de | 77 MB | 1.2 s | 103 MB | 87 / 147 ms | 287 | - |
| opus-mt_tiny_eng-fra | 18 MB | 0.7 s | 45 MB | 17 / 29 ms | 1252 | 83.9 |
| opus-mt-en-fr | 78 MB | 0.8 s | 104 MB | 85 / 135 ms | 316 | 83.7 |
| opus-mt-tc-big-en-fr | 235 MB | 1.6 s | 281 MB | 144 / 305 ms | 227 | (reference) |

"chrF vs big" is how closely each French model's output matches the large `tc-big` model's output (higher is closer). It is a proxy for quality, not a human reference score. There is no large English-German model to compare against.

All 73 sentences (about 1000 words, 7 minutes of speech) translate in under 1 s with a tiny model and about 3.5 s with a base model.

### Conclusions

1. **Speed is not a constraint.** A 20 s live chunk holds about 50 words. That is about 50 ms with a tiny model and about 200 ms with a base model, next to about 4 s of Whisper per chunk. Translation adds roughly 1-5% to live mode.
2. **The tiny models are already the distilled models.** They are 4x smaller and about 4-5x faster than the base models, use 45 MB of memory, and on this sample are as close to the large model as the base models are (83.9 vs 83.7 chrF). For speed and size, no further distillation is needed.
3. **Quality differences between tiny and base are small and go both ways** in the samples. Tiny kept "Full-Stack-Entwickler" where base wrote "Vollstack-Entwickler", and base invented "Binärbiologie". Tiny made grammar slips ("philosophieren sind", "qui vient transcrit le texte"). Base German mixed formal and informal address (Sie / Du).
4. **Errors shared by every model:** literal translations of terms ("deep fakes" as "tiefe Fälschungen" / "faux profonds", "algorithmic opacity" as "Deckkraft" / "Trübung"), and Whisper's mistakes pass straight through. A bigger model fixes some phrasing but not these.
5. **Quality is the open question, not performance.** It needs judgement from someone who reads German and French (see `samples.md`), ideally on more than one video and on conversational speech, not only an academic monologue.

### Sample review and decision

Reviewed by a non-native reader over the 15 samples: all models are understandable, none is publishable quality. The tiny models have a grammar or meaning error in about 3 of 15 sentences ("philosophieren sind", "qui vient transcrit"); base German is slightly more grammatical but hallucinates more ("Binärbiologie", "Vollstack"); the large French model fixes 4-5 sentences the others get wrong but made the single worst error ("livre explicatif"). Since translation cost is negligible next to Whisper, the real trade-off is download size against quality.

**Decision (2026-10-06):** use the tiny models (`opus-mt_tiny_eng-deu`, `opus-mt_tiny_eng-fra`) for now. Revisit model size once the feature works end to end; a COMET evaluation on a standard test set with human references would be the rigorous way to compare.

### Caveats

- One video, one speaker, one register.
- chrF against another model's output is only a proxy. It cannot show where all models are wrong in the same way.
- The CPU is high-end. Even at 10x slower, the tiny models would still be far cheaper than Whisper.

## Step 2: native build check (2026-10-06)

Goal: confirm CTranslate2 builds and links from Rust on Windows next to `whisper-rs` 0.16, as it would inside Glucose. Done in a standalone project in `%TEMP%\ct2t` (outside the repo, so the app's build cache is untouched) with `ct2rs` 0.10.1 (`default-features = false`, features `ruy` and `sentencepiece`, so no Intel MKL) and `whisper-rs` 0.16.

Findings:

1. **Out of the box it does not link.** `ct2rs` builds CTranslate2 against the static C runtime (`/MT`) and adds `/FORCE:MULTIPLE` to the link; whisper.cpp and the app use the dynamic runtime (`/MD`). MSVC refuses to mix them (LNK2038 `RuntimeLibrary` mismatch).
2. **Switching the whole app to the static runtime does not work either.** With `RUSTFLAGS=-C target-feature=+crt-static` (what `ct2rs` recommends), whisper.cpp still builds with `/MD`, because its CMake setup picks the runtime itself.
3. **Building CTranslate2 against the dynamic runtime works.** It takes two small patches to a local copy of `ct2rs`: its `build.rs` (use `static_crt` only when Rust's `crt-static` is on, set `CMAKE_MSVC_RUNTIME_LIBRARY` accordingly, and drop `/FORCE:MULTIPLE`), and CTranslate2's `CMakeLists.txt` line that hardcodes `MultiThreaded` for static builds (now only a default). Wired in with `[patch.crates-io]`. The app's runtime setup stays as it is.
4. **It runs, with identical output to the Python benchmark**, and both libraries load in one process (Whisper model plus translator).

Speed in Rust (ruy backend, 4 threads) on the same 123 cues, compared with Python (CTranslate2 wheel with MKL):

| Model | Load | Per cue mean / p95 | Batched words/s | Python per cue / words/s |
|---|---|---|---|---|
| tiny eng-deu | 0.13 s | 23 / 41 ms | 691 | 18 ms / 1066 |
| tiny eng-fra | 0.14 s | 27 / 52 ms | 615 | 17 ms / 1252 |

The ruy backend is about 25-50% slower than MKL on this x86 CPU. That is still about 75 ms of translation per 20 s live chunk against about 4 s of Whisper, so it does not matter. Avoiding MKL keeps the build simple and the binary small.

Open items before shipping:

- **Carrying the patch.** Decided (2026-10-11): keep the patched copy vendored in the repo. A fork would keep the repo smaller but adds a second repository to maintain. Optionally, propose the runtime fix upstream to `ct2rs`; once a release includes it, the vendored copy can be dropped for the normal crates.io dependency.
- **Check the full app build.** The standalone project links `whisper-rs` and `ct2rs`; the Tauri app adds more native dependencies, so `pnpm tauri build` must be confirmed.
- **macOS and Linux** have no C runtime split like this, but still need a build check.
- **Build time:** CTranslate2 adds a few minutes to a clean build.

## Implementation notes for later

- **Engine:** native in the Rust backend, next to the live worker, the cue formatter and the cache. CTranslate2 runs these models through `ct2rs` (verified in step 2). A WebAssembly build would be slower in WebView2 and WebKit and would split the pipeline between frontend and backend.
- **Translate sentences, not cues.** One sentence often spans several cues. Translate whole sentences, then split the result back over the original cue timings, then run the cue formatter (line length and reading speed change with the language). Marian's guided alignment gives word alignments that would make that split accurate.
- **Licensing:** the compact `opus-mt_tiny_*` models used by the app are Apache-2.0. Of the larger models used only in the benchmark, `opus-mt-en-fr` is Apache-2.0 and `opus-mt-en-de` and `opus-mt-tc-big-en-fr` are CC-BY-4.0 (attribution required). Check against Glucose's license before shipping any model.
